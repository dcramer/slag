# src/gen: procedural generators

Every generator is deterministic given its seed: same seed (and theme), same output, on every machine.

- `generateLevel` is a pure function of its arguments and of nothing generated before it: the browser builds the next levels ahead in a worker (`src/level-ahead.ts`) and the match takes them through `buildLevel` (`level/pregen.ts`). Module-level caches are fine only if they can't change an answer.
- Reachability questions about one level go through one `ReachCache` (`src/sim/reach.ts`): it re-traces only what a change touches, with exactly a fresh analysis's answer. Pass the level's cache down instead of calling `analyzeReach` again.

- Randomness only from a seeded `Rng`; derive independent streams with `deriveSeed(seed, 'label')` so adding a roll in one place doesn't shift every other stream. No `Math.random`, wall clock, DOM, or imports from `render/`, `input/`, `audio/`, `ui/` (lint enforces this).
- Level pipeline (`level/index.ts`): pick theme → `generateTheme` look → theme sculptor (`level/sculptors/<theme>.ts`, registered in `SCULPTORS`) retried until `level/validate.ts` accepts it → set pieces. Falling back to the legacy sculptor or the flat floor counts as `fallback`, and tests assert it never happens.
- Solvability policy: almost no level is passable bare. Each asks for one part, or two on a theme's `TWO_PART_ASK` share of levels (tuned so each theme lands near `TWO_PARTS` needing two; a new theme starts at `TWO_PARTS` and gets an entry once `pnpm level --stats` shows its share), decided once per level by `rollChallenges`, and the pipeline rejects a bare-passable sculpt until `LAST_RESORT`. Every level is proven solvable with at most `MAX_BRIDGES` static `BRIDGE_W` strips, and `level.solution` is that count: `generateCrate` must always cover it, so it has to be the real minimum. Ask `src/sim/reach.ts`; never hardcode jump distances. Size hard crossings with `hardGap(rng, parts)` and easy ones with `easyGap` where the ledge can be run on, `hopGap` from anything shorter. Keep landmarks off a hard crossing's banks (`keepClear`).
- Matches stay winnable (`level/winnable.ts`): a match keeps a plan of at most `MAX_BRIDGES` bridges that reaches the flag while keeping clear of every part's barrier (`sim/props/barrier.ts`), and refuses a placement that leaves none. A level starts from `level.solution`, so set pieces go in only if it still holds that way (`planHolds`, the placer's `keep`).
- Mostly open: `level/routes.ts` scores how much of the fastest route has no alternative lane (`MAX_SHARED`), with the solution's parts in place, on the graph `reach.ts` produces. `judge` reports it, the pipeline enforces it, and `level/lanes.ts` adds a second route to a sculpt that lacks one. Give it a head start: record hard crossings with `hintGap` so lanes stay off them, set `g.carve` in solid rock, and leave air above the ground route.
- Weather (`level/weather.ts`) is rolled after the terrain is final and can only be turned down, never reshape anything, so it can't move the parts shares. Anything new that touches the sim needs a gate there, proved on `analyzeReach`; its `airs` argument runs the ghost in a steady side wind.
- Decide "does this level get a challenge" with `rollChallenges`, which is fixed per level. A per-attempt roll is silently undone by retries, because harder shapes get rejected more.
- Set pieces (`setpieces/`): per-theme `Recipe` lists (`<theme>.ts`, in `SET_PIECE_RECIPES`) built from `builders.ts` and validated by simulation in `place.ts`. They are ordinary `PlacedProp`s with `owner = -1` and uids from `SET_PIECE_UID`, stored on `level.setPieces`, avoid protected rects, and must not cut the path.
- Looks (`theme/presets.ts`, `RECIPES`): palette, sky, skyline, terrain material, liquid, decor, grade per theme. A theme must read as itself at a glance.
- A theme changes how you move only through shared pieces, never a new physics path: its sculptor lays per-tile ground (`Shape.ground`, kinds in `sim/ground.ts`; glacier ice via `glaze`), and `THEME_GRAVITY` in `level/profile.ts` sets its gravity on Auto (space). reach.ts and every ghost walk on both, and sculptor gaps are measured at the level's gravity, so the solvability policy holds unchanged.
- Player prop archetypes (`props.ts`): `RECIPES` + `ARCHETYPE_WEIGHTS`. A recipe rolls a part's identity, then returns `sized`, which may only scale: no rolls in it, and no size words in names (`rollPart` adds them). `generateRoster` is the match's short list, from the seed alone and with a longer roster starting with the shorter one; `generateCrate` draws only from it, always with a bridge and a hazard.

Verify: `pnpm level <seed> --theme <t>` for the ASCII map, `pnpm level --stats 50` for fallbacks, timing and `needBridges`, and `pnpm shot levels --themes all` to look at the result. When you tune a share on purpose (parts needed, styles, set piece variety), run `pnpm test:stats` too; otherwise leave it to CI.
